# 📸 Photo Agent — индекс фотографий для подбора по постам

Инструмент описывает папку с фотографиями и создаёт «картотеку», по которой ИИ-агент подбирает нужное изображение к посту для мессенджера.

Изображения анализируются **Vision-моделью Yandex AI Studio** (qwen3.6-35b-a3b), которая:
- **точно распознаёт** содержимое фото (предметы, людей, надписи) и **не выдумывает** того, чего нет (в отличие от некоторых других моделей);
- переименовывает файлы с сырыми именами (`UUID`, `img_01`) в осмысленные русские названия;
- пишет краткое описание в метаданные (EXIF) JPG-файла;
- формирует индекс (`индекс_фото.jsonl` + `.csv`) — им и пользуется агент.

---

## Что входит

| Файл | Назначение |
|------|-----------|
| `обработчик_фото.py` | Сканирует папку, описывает фото, переименовывает, пишет EXIF и индекс |
| `поиск_фото.py` | Находит подходящие фото по тексту поста (семантический поиск) |
| `индекс_фото.jsonl` | Построчный индекс для агента (генерируется) |
| `индекс_фото.csv` | Тот же индекс в табличном виде для Excel (генерируется) |
| `.env.example` | Шаблон конфигурации. Скопируйте в `.env` и заполните |

---

## Требования

- **Python 3.10+**
- Пакет: `piexif` (для записи EXIF). Установка:
  ```bash
  pip install piexif
  ```
- Аккаунт **Yandex Cloud** и работает **Yandex AI Studio** (Vision / мультимодальная модель).

---

## Настройка

1. Скопируйте шаблон конфигурации:
   ```bash
   cp .env.example .env        # Linux/macOS
   copy .env.example .env      # Windows
   ```
2. Заполните `.env`:
   ```
   YANDEX_API_KEY=AQVN...          # API-ключ сервисного аккаунта
   YANDEX_FOLDER_ID=b1g...         # идентификатор каталога
   YANDEX_MODEL=qwen3.6-35b-a3b    # vision-модель
   ```
   ⚠️ **`.env` содержит секреты — он в `.gitignore`, никогда не пушите его.**

   Где взять:
   - `YANDEX_API_KEY` — консоль Yandex Cloud → Сервисные аккаунты → API-ключ.
   - `YANDEX_FOLDER_ID` — та же консоль, на странице каталога (вид `b1g...`).
   - У сервисного аккаунта должны быть права на каталог (роль `editor` / `admin` или `ai.languageModels.user`).

## Как пользоваться

### Шаг 1. Обработать папку с фото

```bash
python обработчик_фото.py "путь/к/папке_с_фото"
```

Что сделает:
- найдёт все JPG/JPEG/PNG/WebP (включая подпапки);
- опишет каждое через Vision;
- переименует файлы с «сырыми» именами в русские (например `img_01.jpg` → `ночная_баня_в_снегу.jpg`);
- запишет заголовок и описание в EXIF для JPG;
- создаст/обновит `индекс_фото.jsonl` и `индекс_фото.csv` **в этой папке**.

Опции:
```bash
# предпросмотр без изменения файлов
python обработчик_фото.py "папка" --dry-run
```

> 💡 **Важно про повторные запуски.** Скрипт описывает файлы заново при каждом запуске. Для новой порции фото лучше положить их в отдельную папку (свой проект), очистить старые индексы или запускать dry-run.

### Шаг 2. Найти фото по посту

```bash
python поиск_фото.py "текст поста" "папка/с/индексом"
```

Пример:
```bash
python поиск_фото.py "уютная деревянная веранда с гирляндами" "мои_фото"
```
- ищет по нескольким папкам сразу:
  ```bash
  python поиск_фото.py "запрос" "папка1" "папка2"
  ```
- сколько результатов показать:
  ```bash
  python поиск_фото.py "запрос" "папка" -n 10
  ```
- вывод в JSON (для агента):
  ```bash
  python поиск_фото.py "запрос" "папка" --json
  ```

Как ранжируются результаты: **совпадение в ключевых словах > в заголовке > в описании**. Поиск учитывает падежи и словоформы (нормализация).

## Формат индекса (JSONL)

Каждая строка — одна запись:
```json
{
  "filename": "весенние_почки_ивы_на_ветке.jpg",
  "path": "C:\\...\\весенние_почки_ивы_на_ветке.jpg",
  "title": "Весенние почки ивы на ветке",
  "description": "На переднем плане крупным планом изображена тонкая ветка ивы...",
  "keywords": ["ива", "весна", "почки", "природа", "лес", "макро"],
  "notes": ""
}
```

## Возможные проблемы

- **`HTTP 403 Permission ...` при обработке** — у сервисного аккаунта нет прав на каталог. Выдайте роль `editor`/`admin` или `ai.languageModels.user`.
- **`Unknown folder ...`** — в `YANDEX_FOLDER_ID` не каталог, а ID ключа. Нужен именно `b1g...`.
- **Файлы не переименовываются** — скрипт переименовывает только файлы, в имени которых **нет кириллицы**. Уже осмысленные имена не трогаются.
- **PNG/WebP без EXIF** — в эти форматы описание не записывается (только в индекс). Обычное поведение.

## Безопасность и структура

- `.env` — в `.gitignore`, содержит реальные ключи. 🔒
- Пользовательские фото и сгенерированные индексы — тоже в `.gitignore` (репозиторий хранит только код).
- Рабочая схема: **внешняя папка с фото + `обработчик_фото.py` рядом** → индексы создаются рядом с фото, а не засоряют репозиторий.
