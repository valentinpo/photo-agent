# Изменения относительно первой версии

Ниже — что обновлено/добавлено с момента первой версии инструмента
(сборка кода для GitHub). Первая версия описывала фото через **GigaChat** и
имела только `обработчик_фото.py` + `поиск_фото.py`.

---

## 1. Движок описания сменён: GigaChat → Yandex AI Studio Vision

**Причина.** GigaChat-3-Pro при распознавании фотографий **сильно галлюцинировал**:
придумывал людей, животных и сюжеты, которых на снимке не было
(«девушка с книгой», «лошади на заснеженном поле» — а на деле там были
продукты/баня/веранда). Это ломало всю задачу подбора фото по посту.

**Решение.** Обработка фото переведена на **Yandex AI Studio** (модель
`qwen3.6-35b-a3b`, Responses API, OpenAI-совместимый эндпоинт
`ai.api.cloud.yandex.net/v1`). Яндекс точнее распознаёт содержимое кадров
(предметы, надписи) и **не выдумывает отсутствующего** — описания стали
достоверными и полезными.

Конфигурация теперь:
```
YANDEX_API_KEY=AQVN...
YANDEX_FOLDER_ID=b1g...
YANDEX_MODEL=qwen3.6-35b-a3b
```
(старые GigaChat-переменные `GIGACHAT_*` больше не нужны).

---

## 2. Логика переименования стала умнее

- Переименовываются **любые «сырые» имена** без кириллицы: не только UUID
  (`043d…jpg`), но и нейтральные (`img_01.jpg`) — они получают осмысленные
  русские названия.
- **Уже осмысленные кириллические имена не трогаются** повторными запусками.
- Исключены бесконечные переименования при нестабильных ответах модели.

---

## 3. Индексация стала идемпотентной (без дублей)

`обработчик_фото.py` раньше **дописывал** записи в `индекс_фото.jsonl`,
из-за чего повторный прогон плодил дубли. Теперь индекс **пересобирается
начисто с дедупликацией** (одна запись на файл).

Добавлены режимы запуска:
```bash
# описать только НОВЫЕ фото (уже проиндексированные пропустить)
python обработчик_фото.py "папка" --skip-existing

# пересобрать индекс заново
python обработчик_фото.py "папка" --new-index

# предпросмотр без изменения файлов
python обработчик_фото.py "папка" --dry-run
```

---

## 4. Добавлен навык индексации (для управления через агента)

Новый навык **`photo-agent-index`** (папка `.claude/skills/photo-agent-index/`).
Теперь агентом GigaTool можно управлять индексацией голосом/текстом:
- «обработай фото в папке …» → запустит `обработчик_фото.py`;
- «добавил новые фото, запусти обработку» → запустит с `--skip-existing`;
- «обнови индекс» → пересобрать.

Это отдельный навык от поискового — **не пересекается** с `photo-agent-search`.

---

## 5. Существующий поисковый навык остался

`photo-agent-search` — подбор фото к посту — живёт в `.claude/skills/photo-agent-search/`.
Не менялся по сути, лишь дополнен подсказкой про обновление индекса
(`--skip-existing`) при добавлении новых снимков.

## 6. Структура проекта (эта версия)

```

├── поиск_фото.py                 # семантический поиск фото по посту
├── .claude/skills/

└── .gitignore                    # исключает .env, фото, индексы
```

## Перенос на другую машину

- Рабочий проект: скопируйте папку с кодом + **свой `.env`** + папки с фото
  (индексы создадутся заново).
- Навыки переносятся в `~/.config/gigatool/skills/` (для глобальной
  доступности) или остаются в `.claude/skills/` проекта (доступны в этом проекте).
- После установки навыков — перезапустите приложение, чтобы они подхватились.
